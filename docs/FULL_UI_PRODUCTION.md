## 并行分工

按 UI_SCOPE.json 的 batch 分配：core 为专用制作聊天（含 01–10、56–58），table 为牌局工（11–22、53–55），modes 为模式工（23–36），support 为配套工（37–49、59–60），components 为协调者（50–52）。各工仅写本批 designs/ui/<batch>/、prompts/<batch>/ 与批次说明，根统计由协调者维护。原 image 项目只读。

## 逐项完成标准

- 每个完整页面有独立原生画面，公共弹窗／控件／牌面为专项图板。不得以多屏缩略拼图、占位图或缩放代替完整页面与原生细节。
- 实际附上两张风格图调用内置 image_gen；生成前重读 AGENTS 与配置；保存提示词及每图 generation.json；实际看图检查风格、控件、文字与布局。
- <id>.states.json 逐一列 requiredStates、文案、行为、禁用原因、共享素材依赖及 coverage（rendered / shared_component / specified_only）。状态说明不是已画状态。共享控件可用于同源皮肤与原生动态文字；特殊主状态应单独生成。
- 每图记录实际原生尺寸、哈希、来源与未披露的实际型号／质量。视觉检查通过标记 design_ready_user_review，不能自称用户批准。
- 各批 README 索引完整；失败保留 pending/needs_fix 与原因；全量核对真实文件与记录后统计。
- 本合同交付视觉设计、通用素材与状态规范。客户端、服务器、支付或社交发送的实际接入不在此次美术完成声明内。
